SPIDEY SENSEPART 2 · HOW IT WORKS
Here's the hardware. The Neon glasses plug into their Companion phone, which streams over its own hotspot to the MacBook, so we don't depend on venue Wi-Fi. The Dot and its El Jefe controller talk Bluetooth, the radar runs its own little server, and an iPhone app shows everything live.

Architecture

Source → detector → triggers → haptics.

The engine is a simple loop: a source gives frames with gaze, the detector asks Haiku about them, the triggers decide whether to fire, and the sink plays a pattern on the Dot over Bluetooth. Every stage is swappable in config, fake or real, which is how we built and tested it all in parallel. Every event also goes out over a WebSocket to the phone.

The detector

One Haiku call per tick. Everything in it.

IN
newest frame, 384 px, gaze drawn in
+ 3 labelled frames for temporal triggers
+ built-in hazards and every plain-English trigger
OUT (streamed, strict JSON)
hazard · urgency · x · seen_by_user → act now
triggers · bbox · why → follows

Frame → cue 0.92 s median, 1.20 s p90 (was 1.28 s). ~3 results/s, 125/125 correct on test scenes.

SPIDEY SENSEPART 2 · HOW IT WORKS
There's only one model path. Each tick we send Haiku the newest frame plus every trigger the user wrote in plain English, all in one call. The answer streams, and the urgent fields come first, so built-in hazards fire before the rest of the JSON arrives. Two calls overlap, which got us from 1.28 to 0.92 seconds median.

Attention model

"Seen" comes from your real gaze.

Engine checks when the gaze point last fell inside the object's box → looked_at_s_ago.

looking_at
looked ≤ 0.6 s ago
You're on it right now.
noticed
within notice_memory_s (3 s)
Looked recently. Stay quiet.
unseen
not looked at
Eligible to buzz.
We don't trust the model to guess whether you saw something. Haiku returns a bounding box, and the engine keeps about five seconds of real gaze samples from the glasses. If your gaze was inside that box recently, you've noticed it and we stay quiet; if not, it's unseen and can buzz.

Temporal layer

Change over time, not one snapshot.

3 labelled frames in the same Haiku call. Code keeps the trend; only relative signals, no metres from a camera.

gap
subject ↔ target, in body-heights
loom
box area vs last tick (>1 = coming at you)
ordinal
closer / same / farther
touching
yes / no

Fires on a consistent trend for ≥ 3 ticks (or touching) · hysteresis + cooldown so it doesn't chatter.

Some hazards are about change, like a person getting closer to the water. For those triggers Haiku sees three frames labelled with their times, and returns boxes plus closer-or-farther. The code remembers the trend using only relative measures, like the gap in body-heights, and fires once it's consistent for three ticks.

SPIDEY SENSEPART 2 · HOW IT WORKS
The Dot has three channels: vibration, light and heat. We built a small vocabulary: urgent is a sharp triple click and strong buzz in red, pulse is a heartbeat in pink, ambient is a soft blue hum. Intensity works by swapping to weaker waveforms, and warmth is hard-capped at 40 degrees with automatic shut-offs.

Reverse-engineering win

Cutting the cable: 361 → 117 ms.

1. DataFeel only shipped USB for Python.
2. Inside their NuGet DLL: the Nordic UART service UUIDs, carrying the same Modbus RTU frames.
3. A fake serial port over Bluetooth → stock SDK works unchanged.
4. Fastfire: 6 writes → 2 before the buzz starts.
TRIGGER → BUZZ, MEDIAN
Bluetooth, stock SDK361 ms
6 sequential writes × ~60 ms
Bluetooth, fastfire117 ms
2 writes · worst 150 ms
USB cable (reference)48 ms
The Dot only had a USB Python SDK, and a cable to your laptop isn't a wearable. I found the Bluetooth protocol inside DataFeel's C# NuGet package: Nordic UART carrying the same Modbus frames. A fake serial port made their SDK work unchanged, and cutting a trigger from six writes to two took it from 361 to 117 milliseconds.

The iPhone app

See why it buzzed. Teach it new senses.

The app is the window into the system. The Log shows every buzz with Haiku's reason, Senses is where you write new triggers in plain English like 'someone holding a knife and I haven't looked at it', and Haptics checks each hop of the link with live milliseconds. It finds the Mac by itself over Bonjour, no setup.
