Reverse-engineering win

Cutting the cable: 361 → 117 ms.

1. DataFeel only shipped USB for Python.
2. Inside their NuGet DLL: the Nordic UART service UUIDs, carrying the same Modbus RTU frames.
3. A fake serial port over Bluetooth → stock SDK works unchanged.
4. Fastfire: 6 writes → 2 before the buzz starts.
TRIGGER → BUZZ, MEDIAN
Bluetooth, stock SDK361 ms
6 sequential writes × ~60 ms
Bluetooth, fastfire117 ms
2 writes · worst 150 ms
USB cable (reference)48 ms
The Dot only had a USB Python SDK, and a cable to your laptop isn't a wearable. I found the Bluetooth protocol inside DataFeel's C# NuGet package: Nordic UART carrying the same Modbus frames. A fake serial port made their SDK work unchanged, and cutting a trigger from six writes to two took it from 361 to 117 milliseconds.
